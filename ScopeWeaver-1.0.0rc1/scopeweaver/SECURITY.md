# Security policy

## Supported builds

`1.0.0rc1` is a release candidate. Until a stable release exists, fixes target the current
candidate branch. This project has not received an independent security audit.

## Reporting a vulnerability

For scope bypasses, unintended egress, report injection or secret exposure, use GitHub's
**Report a vulnerability** / private advisory feature **if the repository owner has enabled
it**. No reporting service, email address or response SLA is invented by this source tree.
If a private channel is unavailable, ask the maintainer for one in an issue without posting
sensitive reproduction details. The publishing owner must configure a private channel
before a stable release.

Include the version, platform, a minimal synthetic configuration, a local reproduction and
the expected boundary. Use loopback targets and redact all client data.

## Trust model

Operators approve both targets and auxiliary DNS/WHOIS endpoints. Built-in modules route
egress through a common transport. DNS answers must fit the IP allowlist in full; connections
use a selected numeric address. HTTP cookies are not replayed, environment proxies and
automatic redirects are disabled. No HTTP application data is fetched with certificate
verification disabled. A failed certificate may be retrieved in a separate TLS-only
diagnostic handshake to document the failure.

An installed and explicitly enabled plugin can execute arbitrary Python. The plugin API is
an engineering contract, **not a sandbox or a firewall**. The framework cannot constrain
malicious plugins, compromised dependencies, a hostile OS, external routing changes or
traffic generated by the approved target itself. Use egress controls for defense in depth.

GET and OPTIONS are used for web checks; a broken application can attach side effects to
any method. Review application semantics and obtain approval before testing. TLS and TCP
connections can appear in monitoring and may affect fragile legacy systems.

## Data handling

Password analysis accepts only explicitly marked synthetic datasets. Values and hashes
are omitted from results. This declaration cannot prove that an operator supplied synthetic
data. AD reports may contain identity and permission metadata; WHOIS may return personal
registration data. Treat reports and logs as confidential. POSIX-created report and audit
files use private permissions; Windows protection depends on the destination directory ACL.

Logs are flushed JSONL events, not signed or tamper-evident records. Ctrl+C and the stop file
cancel pending work and save completed module results where possible. SIGKILL, power loss,
a second forced interrupt or an unwritable output directory can prevent final output.
